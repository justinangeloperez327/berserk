# Berserk v1.0.0

v1.0.0 establishes Berserk's first stable public API baseline.

## Stable application surface

New application code should use:

- instance-scoped route registration through `app.route()`;
- request-scoped authentication through `Request::user`, `Request::can`, and `Request::authorize`;
- typed handlers, route parameters, FormRequest validation, and explicit application state;
- Claw ORM through request/database scopes with bound query values;
- feature-gated optional services and async support.

The pre-1.0 direct application verb shortcuts and `Request::principal()` compatibility alias were removed before the stable release.

## Release guarantees

- Version: `1.0.0`.
- Minimum supported Rust version: 1.88.
- Public API compatibility follows semantic versioning.
- Breaking public API changes require a new major release.
- Security, correctness, Rust safety, and explicit application boundaries remain release priorities.
- Publication remains an explicit owner-controlled action.

## Operational baseline

The stable baseline includes bounded HTTP serving, graceful shutdown, request logging, tracing and metrics primitives, explicit database scopes and transactions, authentication and authorization primitives, storage/client safety boundaries, in-memory testing helpers, and release/package verification.

Known deployment boundaries remain documented in [known-limitations.md](known-limitations.md) and [support-policy.md](support-policy.md).

## Upgrading from v0.9.0

See [upgrade-notes.md](upgrade-notes.md). In particular, migrate direct `app.get/post/put/patch/delete` calls to `app.route().*` and replace `Request::principal()` with `Request::user()`.
