# Berserk v0.8.0

v0.8.0 strengthens the production and observability surface while keeping Berserk vendor-neutral.

## Health

`HealthRegistry::snapshot()` returns a programmatic view of readiness:

```rust,ignore
let snapshot = health.snapshot();

if snapshot.ready {
    // dependencies are ready
}

for check in snapshot.checks {
    println!("{}: {:?}", check.name, check.status);
}
```

The existing liveness and readiness HTTP responses remain available. Readiness rendering now uses the same snapshot model, so programmatic and HTTP results share one source of truth.

## Metrics

`MetricsSnapshot` provides summary helpers:

- `completed()` for requests no longer active;
- `average_duration_us()` for completed-request average duration;
- `healthy()` for a simple no-recorded-failures check.

Raw counters and Prometheus output remain available.

## Logs

`MemoryLogSink` now supports `take()` and `clear()` in addition to non-destructive `events()`. This makes operational tests and controlled log collection simpler without adding global logging state.

## Tracing

`TraceContext` exposes its trace flags and whether the sampled bit is set:

```rust,ignore
let context = request.trace_context().unwrap();

if context.sampled() {
    // attach richer diagnostic context
}
```

Trace generation and parsing continue to use W3C-style `traceparent` values.

## Production boundary

Berserk still does not terminate TLS and does not infer trusted proxy topology. Deployment-specific HTTPS termination, proxy trust, log shipping, and metrics collection remain explicit infrastructure decisions.

## Compatibility

- Rust 1.88 remains the MSRV.
- Existing operational middleware APIs remain available.
- The new APIs are additive.
