# Berserk / Claw ORM 1.2.0

This release completes the Claw relationship scope on the stable 1.x API baseline. It also carries the migration improvements previously developed on the 1.1 branches. Merge, tagging, and crates.io publication remain separate maintainer actions.

## Relationship changes

- All four relationship types return ordinary `ModelQuery` values through `query_for`.
- BelongsToMany supports parameterized single/batch attach and detach, explicit detach-all, and atomic sync with `SyncResult`.
- Eager loading preserves shared related records and duplicate pivot rows without requiring model cloning. Live signed/unsigned integer keys match correctly.
- Real eager-query paths, query counts, pagination, multiple relationships, malformed data, constraint failures, and transaction rollback are tested.
- Original 1.0 explicit `load(connection, ...)` methods remain as deprecated forwarders. HasOne continues returning RelatedSet with cardinality enforcement.

See the [relationship guide](relationships.md), [runnable example](../crates/claw/examples/relationships.rs), and [upgrade notes](upgrade-notes.md).

## Design and compatibility decisions

`ModelQuery`, `Query`, `Connection`, `Transaction`, `Value`, and `DatabaseError` are reused. The database builder adds `constrain_in` to keep relationship parent restrictions effective across ordinary OR filters. No parallel query builder, new external dependency, model Clone bound, or error hierarchy is introduced.

Duplicate pivot rows represent actual stored links and remain visible. Database UNIQUE and foreign-key constraints define data integrity. Sync changes key membership, not pivot row multiplicity. Explicit key accessors remain because the existing model trait cannot infer foreign fields from column names. A separate RelatedOne type would change the existing public output without enough benefit in this minor release.

## Version and validation

Workspace packages and internal requirements are synchronized at 1.2.0. Generators derive their framework version and Rust requirement from package metadata. Both the workspace lockfile and the independent minimal example lockfile are updated; the external example's own application version remains 0.1.0 intentionally.

The release planner rejects unsynchronized workspace versions and stale internal dependency requirements. Rust 1.88 remains the minimum version.

Required local gate:

```sh
cargo fmt --all
cargo fmt --all -- --check
cargo check --locked --workspace
cargo test --locked -p claw-orm
cargo clippy --locked -p claw-orm --all-targets -- -D warnings
cargo +1.88.0 check --locked --workspace --all-targets --all-features
python3 scripts/verify_generators.py
python3 scripts/release_plan.py --version 1.2.0
```

The release validation must also pass the full quality job, Windows/macOS tests, PostgreSQL 15–18 and MySQL 8.4 live relationship contracts, bundled SQLite tests, package and release artifact checks, and repository hygiene. A queued or running job is not completion evidence.

## Outside this release

Nested eager traversal, polymorphic relationships, pivot models, lifecycle hooks/events, observers, automatic timestamps, soft deletes, dynamic model properties, deep relationship chains, declaration macro systems, and nested transactions are not added. Sync does not serialize concurrent writers; see the documented coordination requirements.
