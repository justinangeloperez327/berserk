# Berserk v0.9.0

v0.9.0 begins Berserk's 1.0 stabilization window. The release intentionally adds very little new framework surface.

## Preferred application surface

New application code should prefer:

- `app.route()` for route registration and scoped middleware;
- `Request` for request-local state, authentication, authorization, database access, and application services;
- explicit `App` registration for configuration and optional services;
- Claw query builders with bound values and explicit terminal operations;
- opt-in operational middleware and feature-gated components.

These APIs are the current candidates for the 1.0 application surface.

## Compatibility APIs

Some earlier convenience surfaces remain available during the pre-1.0 transition. They are not being expanded:

- direct application route shortcuts;
- request-global authentication facade usage;
- compatibility aliases such as `Request::principal()`.

New code should use the scoped alternatives documented in the public API guide.

## Utilities

`Arr` and `Str` remain available as explicit root imports:

```rust,ignore
use berserk::{Arr, Str};
```

They are no longer exported by `berserk::prelude::*`. This keeps the default prelude focused on application framework primitives instead of general helper collections.

## Reliability

v0.9.0 also carries canonical formatting fixes discovered after the v0.8 merge and adds a public-surface contract test for the preferred route/request API.

## Compatibility

- Rust 1.88 remains the MSRV.
- No supported database or platform line is removed.
- v0.9.x should favor stabilization and bug fixes over new public concepts.
- Any remaining breaking API decision intended for 1.0 must be made and documented before the stable release.
