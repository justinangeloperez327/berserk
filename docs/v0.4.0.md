# Berserk v0.4.0

v0.4.0 establishes the authentication and HTTP-security baseline that was merged after v0.3.0.

## Authentication

- Argon2 password hashing remains isolated in `berserk-auth`.
- Session and personal/API tokens support secure random generation, digest storage, expiry, revocation, and explicit abilities.
- `Request::user()` exposes the authenticated principal.
- `Request::can(...)` checks an explicit ability.
- Applications can configure a guard once with `app.auth(guard)?`.
- Route scopes use concise `.auth()`, `.guest()`, and `.can(...)` helpers while the lower-level middleware contracts remain available.

## Authorization

Authorization retains typed policy support where resource-specific checks are needed. Missing authentication returns 401; authenticated identities that lack permission return 403.

## HTTP security

v0.4.0 adds explicit CORS and security-header middleware with fail-closed validation. Wildcard origins cannot be combined with credentials. HSTS is opt-in because TLS termination is deployment-specific.

## Rate limiting

The existing bounded rate limiter remains available and can key limits using trusted application context, including authenticated identities.

## Compatibility

- Rust 1.88 remains the MSRV.
- Berserk remains sync-first.
- Browser cookie authentication and CSRF policy are not first-class framework features in this release.
- The framework remains pre-1.0, so authentication APIs may still be refined before 1.0.
